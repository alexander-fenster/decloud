## Question

It seems like something is wrong with the automatically generated configuration, or Caddy is unable to reach the port the container listens on. Investigate and either fix or suggest a configuration change.

## Initial Observations (for the team)

- The error log shows Caddy attempting to dial an IPv6 address `[2a03:f480:1:12::7b]:10001`, which looks like a public/host IPv6 address — NOT the Docker bridge address `172.18.0.2`.
- The `decloud` network has `EnableIPv6: false` and the container has no IPv6 address.
- This suggests Caddy is resolving `decloud-durak-live` via host DNS (or some other resolver) rather than the embedded Docker bridge DNS, causing it to hit the public IPv6 of the host instead of the container's IP on the `decloud` network.
- A likely root cause: the Caddy container itself is not attached to the `decloud` network, so Docker's embedded DNS for that network is not used to resolve `decloud-durak-live`.
