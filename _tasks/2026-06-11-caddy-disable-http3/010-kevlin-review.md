## 1. Generated Caddyfile — byte-verified

I dumped the actual output (service with hostname `h3.example.com`, plus the empty
registry). Exact bytes, populated case:

```
# Caddyfile generated by decloud — do not edit by hand.\n
# Re-run `decloud caddy reload` to refresh.\n
\n
{\n
    servers {\n
        protocols h1 h2\n
    }\n
}\n
\n
h3.example.com {\n
    reverse_proxy decloud-foo:8080\n
}\n
```

Empty registry: identical header + global block, terminating at the global block's
closing `}\n` with no trailing site content.

- **Global options block is first.** It precedes every site block — Caddy's hard
  requirement (global options must be the first block). Verified by bytes and by the
  `protoIdx < siteIdx` assertion.
- **Braces balanced**, correct nesting: `{` col 0 → `servers {` (4 sp) →
  `protocols h1 h2` (8 sp) → `}` (4 sp) → `}` (col 0).
- **No double blank lines, no stray indentation.** Exactly one blank line separates
  the header comments from the block, and exactly one separates the block from the
  first site. The loop's leading `fmt.Fprintln(&buf)` (generator.go:47) supplies that
  single separator; Rob correctly did NOT append a trailing blank after the block, so
  the double-blank trap is avoided.
- **No tabs.** The indentation is literal spaces inside Go string args (generator.go
  42–44), so gofmt cannot rewrite them and there is no tab/space mix. Consistent with
  the existing `    reverse_proxy` line (4 spaces) — matches house style, not the
  brief's wrong "tabs by convention" note. Correct call.

`servers { protocols h1 h2 }` is valid Caddy v2 global-options syntax and the omission
of `h3` is the documented mechanism to disable HTTP/3. Correct.

## 3. Test quality (generator_test.go)

Meaningful, not change-detectors:

- `protocols h1 h2\n` positive assertion pins the directive to terminate at `h2` before
  the newline — catches *any* trailing protocol, not just h3. This is the strongest
  single assertion and the right one.
- The two h3 negatives (`protocols h1 h2 h3`, `h1 h2 h3`) are scoped to the directive
  text, NOT a bare `NotContains "h3"`. I verified robustness directly: I ran the
  generator with a `h3.example.com` hostname and the emitted body contains the substring
  `h3.example.com` — yet none of the three assertions trip, because all are anchored to
  the `protocols`/`h1 h2` directive tokens. The hostname-collision trap Linus flagged in
  004 is genuinely closed by construction.
- Indentation assertions (`\n    servers {\n`, `\n        protocols h1 h2\n`) lock the
  4/8-space house style against a future tab regression.
- Ordering via `strings.Index` with `require.GreaterOrEqual(..., 0)` guards before the
  `Less` comparison — mirrors the existing `MultiServiceMultiHostSorted` pattern.
- The renamed `TestGenerator_EmptyInputProducesHeaderAndGlobalBlock` is a legitimate
  contract change (empty output is no longer header-only), not a change-detector hack.
