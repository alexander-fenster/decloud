# Widening a Cobra command's arg count: `MaximumNArgs(N)` + `len(args)` dispatch

When a command currently takes `cobra.ExactArgs(1)` and you want to add a no-arg variant (or widen `ExactArgs(N)` to accept fewer), switch to `cobra.MaximumNArgs(N)` and dispatch in `RunE` on `len(args)`. The existing exit-code matching (`isCobraUsageError`) handles the >N case transparently without any test or matcher update, because Cobra's error string for `MaximumNArgs` and `ExactArgs` both contain the substring `"accepts"`.

## The free contract: `"accepts"` is the matcher

`internal/cli/exit_codes.go:75-85` matches Cobra's "accepts at most N arg(s), received M" string via `strings.Contains(msg, "accepts")`. The same substring is in `ExactArgs`' error ("accepts N arg(s), received M"). Widening from `ExactArgs(1)` to `MaximumNArgs(1)` means the >1-args path still routes to `ExitUsageError` (2) with zero code change. Verified at `_tasks/2026-05-13-status-list-all-services/03-tech-plan.md §0`.

## Recipe

Before (`internal/cli/status.go`, pre-widening shape):

```go
return &cobra.Command{
    Use:  "status <name>",
    Args: cobra.ExactArgs(1),
    RunE: func(cmd *cobra.Command, args []string) error {
        return doOneThing(args[0])
    },
}
```

After:

```go
return &cobra.Command{
    Use:  "status [name]",     // square brackets = optional positional, Cobra convention
    Args: cobra.MaximumNArgs(1),
    RunE: func(cmd *cobra.Command, args []string) error {
        if len(args) == 1 {
            return doOneThing(args[0])
        }
        return doAllThings()
    },
}
```

Three changes, no fourth:

1. `Use:` — `<name>` → `[name]` (Cobra convention for optional positional).
2. `Args:` — `ExactArgs(N)` → `MaximumNArgs(N)`.
3. `RunE:` — branch on `len(args)`. Extract the existing body to its own function (e.g., `runStatusOne`) so the dispatch reads as one branch each.

## Regression lock to add

One test pinning the `>N → ExitUsageError` contract. Example: `TestStatus_TooManyArgsReturnsUsageError`:

```go
err := runRoot(t, "status", "foo", "bar")
assert.NotNil(t, err)
assert.Equal(t, ExitUsageError, ExitCodeFor(err))
```

This test would also pass under the pre-widening `ExactArgs(1)`, because Cobra emits the same `"accepts"` substring for both. The regression value is forward-looking: if a future widening to `MaximumNArgs(5)` accidentally trips through, the test fails because zero-five args no longer route to `ExitUsageError`. Lock now, fail later if drift.

## Why one command beats a sibling `list` subcommand

Operator-tool convention (`kubectl get pods` vs `kubectl get pods <name>`, `git log` vs `git log <ref>`): when the no-arg and one-arg forms return the same shape of information at different cardinalities, they belong to one command name. A sibling `decloud list` forces operators to learn a second name for "the same data" and doubles the doc surface. The dispatch in `RunE` is one `if len(args) == 1` — not "mixing modes," one trivial branch.

Linus's plan-review explicit ratification: `_tasks/2026-05-13-status-list-all-services/04-linus-review.md §1`.

## When NOT to apply

- The no-arg and one-arg forms return **different shapes** (single struct vs list-of-struct, single line vs table). Then the dispatch handler returns to two different writers, and at that point a sibling subcommand might be cleaner. The status case got away with shared output because the multi-row form IS the single-row form repeated; if the multi-row form had to gain a `--format=json` flag and the single-row didn't, the symmetry argument weakens.
- The no-arg form requires extra flags (`--all`, `--namespace`) that the one-arg form doesn't. Then the flag matrix differs by mode, and the dispatch branch carries hidden coupling. Two commands is cleaner.

## Anti-patterns

- Adding a `--all` flag instead of widening to `MaximumNArgs(1)`. The no-arg form IS the `--all` form. The flag is redundant surface area.
- Forgetting to update `Use:` from `<name>` to `[name]`. The `--help` text and Cobra's autogenerated usage line both surface the bracket convention to operators; mismatch tells them the wrong thing.
- Asserting on Cobra's exact error string in tests. `isCobraUsageError`'s substring matcher is the seam; tests assert on `ExitCodeFor(err) == ExitUsageError`, not on the error string itself.
