# Doc-writing notes (Raymond)

- `_docs/` in this project is plain Markdown (`install.md`, `usage.md`) — NOT a Next.js/JSX app. No build step; do not run `next build`.
- Operator-facing port/protocol facts live in `_docs/install.md` (§3 firewall, `caddy up` steps) and `_docs/usage.md` (§ caddy up bullet ~196, network model §6 ~320). README.md also lists host ports (~61 feature line, ~124 prerequisites).
- Architecture/"why" rationale lives in `_ai/decisions/*.md`, deliberately NOT in `_docs/` (see caddy-runs-in-container.md footer). When a Decision's premise is field-disproven, amend with a dated subsection — never delete the original reasoning.
- **Plans are history, code is truth, the decision record outlives both.** `_tasks/` is immutable by convention: do NOT retro-edit a plan to hide a wrong turn, even one you wrote. A silently corrected plan is worthless as history — the whole value of the audit trail is that it records what people actually believed when they decided. Fix the decision record, and note the divergence in a review so nobody reads the stale plan in a year and "corrects" the docs back to the lie. Live instance: `002` §5 / `003` §8 still say the compression reset is "silent"; it warns. Recorded in four places, erased in none. (Linus's ruling, `009` §1 + §8.4; Don accepted it without reservation, `002` §10.2.)
- HTTP/3 is disabled (`servers { protocols h1 h2 }` in the generated Caddyfile). UDP/443 is still published by `manager.go` runOpts() but inert. There is NO user-facing protocol config flag (hardcoded in `internal/caddy/generator.go`); `caddy.protocols` is only an M3 forward-looking idea.
- Site blocks carry `encode zstd gzip` by default; `--no-compression` (TOML `disable_compression`, absent/false = ON) omits it per service. So there IS one user-facing per-service Caddy knob — unlike `protocols` above, which stays hardcoded. Flag is not sticky (resets on redeploy, with a WARN); rationale in `_ai/decisions/http-compression-on-by-default.md`.
- TOML examples of top-level `ServiceConfig` scalars (`strategy`, `disable_compression`, ...) MUST show the key above the first `[table]` header — TOML binds a bare key to the preceding table, so an appended key decodes as `state.<key>` and the strict loader (`DisallowUnknownFields`) rejects the file with `ErrUnknownField` → exit 10. Verified empirically with a throwaway test against `fsStore.Load`; a "just append it" example would hand the operator a broken file.
- No Docker on the dev box → never write "validated" for Caddyfile changes; say "byte-asserted; pending operator `caddy validate`."
