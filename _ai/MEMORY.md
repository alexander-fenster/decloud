# _ai library index

Tactical reference for the Decloud codebase. Each file is a dense decision record or a non-obvious gotcha. Keep entries one-line where possible; point at code or task files for detail rather than re-explaining.

## Architecture decisions

- `decisions/m1-scope.md` — M1 = server-side `decloud deploy service` with `recreate` strategy; why "client first" / "bootstrap first" / "jobs first" were rejected; full M1→M7 milestone sequence.
- `decisions/secrets-split.md` — config TOML mode 0644 + `secrets/<name>/env.toml` mode 0600 in 0700 dir; load/save/delete ordering that produces only the recoverable "config-without-secrets" failure mode.
- `decisions/schema-versioning.md` — `pelletier/go-toml/v2` strict mode + `schema_version` integer; bump only on semantic breaks, never preemptively; M1/M2/M7 all write version 1 (mounts populated since M2, secret-files at M7).
- `decisions/m1-test-strategy.md` — M1 ships unit-tests-only per maintainer directive; Gomock for `Store`/`Capturer`/`Driver`/`Generator`/`Reloader`, real bash for `internal/envcap`, ten-item handoff receipt is the manual-CI bridge until GitHub Actions lands.
- `decisions/no-magic-zero-modes.md` — `--port=0` rejected at validation, NOT treated as "worker mode"; M5 workers get a separate `deploy job` command. Why folding workload shapes into one command via magic values produces 200-line if-else trees.
- `decisions/caddy-runs-in-container.md` — Caddy is `decloud-caddy` on the `decloud` Docker network, not a host systemd unit; why every host-side variant (host.docker.internal, --network host, /etc/hosts injection, resolvers 127.0.0.11, dnsmasq, sidecar) was rejected; dual-stack publishing, named-volume ACME state, deploy-failure recovery contract. Amendment 2026-06-24: `NetworkEnsure` creates the bridge `--ipv6 --subnet fd00:dec0:11d::/64` on FRESH installs (NAT66 egress, `ip6tables` default-on in Docker 27+); existing networks are a strict no-op, NOT auto-upgraded (no docker command toggles `EnableIPv6`; upgrade is manual out-of-band `network rm`+recreate); IPv4 subnet still auto-allocated so `ContainerIP` read unchanged; `deploy/service.go` now uses `caddy.NetworkName` not the `"decloud"` literal.
- `decisions/http-compression-on-by-default.md` — every site block gets `encode zstd gzip`; `--no-compression` (TOML `disable_compression`, absent/false = ON) opts a service out. Why on-by-default despite BREACH/CRIME (CRIME is TLS-level, not response-body; BREACH needs a secret reflected in a compressed body — not our call to make for the backend); why the knob buys **zero bytes** and exists only for the streaming hang; why `match` CANNOT fix that hang (caddy#6293 — the encode wrapper installs on request headers alone, before Content-Type is knowable, and swallows a pre-body `Flush()`); gzip-vs-zstd ordering as negotiation not advertisement. **Upgrade note: the first `decloud caddy reload` after this ships turns compression on for every existing service.**
- `decisions/journald-log-driver.md` — every Decloud container (services AND `decloud-caddy`) is started with `--log-driver=journald --log-opt tag=decloud/<service>`; why journald not syslog; why `Service` flows as an explicit field not derived from `Name`; the two driver-layer sentinels (`ErrEmptyService` + `ErrInvalidService`) and the slash-rejection invariant; `docker start` does NOT re-emit log flags. Cross-redeploy log query: `journalctl CONTAINER_TAG=decloud/<service>` (exact-match, not regex).

## Implementation patterns (reusable)

- `cobra-init-pattern.md` — `PersistentPreRunE` for filesystem-touching init + EACCES/ENOENT graceful fallback; what saves `decloud --help` from exit 70 on a fresh box.
- `cobra-stringarray-not-stringslice.md` — `pflag.StringSliceVar` splits on commas; use `StringArrayVar` for `--mount` and any flag whose values can contain commas (paths, mount specs). Use `StringSliceVar` only for hostnames/tags where comma-as-separator is desired.
- `explicit-inputs-not-globals.md` — `logging.Init(root string) error` takes the resolved root as a parameter, does NOT re-read `DECLOUD_ROOT`. Why structural contracts beat procedural ones (setter pattern, viper read, env-fallback all rejected).
- `cli-flag-surface-coherence.md` — every CLI flag has four surfaces (runtime check, error string, `--help` text, `_docs/usage.md`); change one, audit all four. The bug class the review-findings task fixed AND nearly re-introduced.
- `error-wrap-discipline.md` — `%w: %w` not `%w: %v`; grep recipe + the regression test that locks it in (`TestDeploy_BuildErrorPreservesInnerSentinel`). Companion rule: one sentinel per chain when the chain crosses an exit-code router (M2 dual-sentinel-chain footgun: `parseMountFlags` had to strip `ErrInvalidMount`'s wrap or exit-code routing would flip on case-reorder).
- `optional-input-two-layer.md` — leaf-consumer defensive return + orchestrator guard, both layers, no coupling; the `Capture("")` / `if envFile != ""` shape generalizes.
- `gomock-inorder-sequencing.md` — pin orchestrator step ordering with `gomock.InOrder`; contract test not implementation test.
- `cobra-arg-count-widening.md` — to add a no-arg variant to an `ExactArgs(1)` command: `MaximumNArgs(1)` + `len(args)` dispatch in `RunE`, and `Use: "<name>"` → `"[name]"`. Exit-code routing is free — `isCobraUsageError` matches on `"accepts"`, which both error strings contain. Why one command beats a sibling `list` (kubectl/git convention) and the two cases where it doesn't (different output shapes; mode-specific flags). Do NOT add `--all` — the no-arg form IS the `--all` form.
- `two-readers-of-one-registry.md` — two consumers of one data source with different corruption tolerance get **two methods, not a `strict bool`**: `Store.List` silently skips unloadable services (the Caddyfile path must not crash on one broken service), `Store.ListNames` returns every registered name (the status path exists to show the broken ones). The divergence is the contract. Locked by a three-test triangle that fails if someone "consolidates" them behind a flag.
- `presentation-string-in-domain-struct.md` — a diagnostic field that is printed verbatim and never `errors.Is`-matched should be `string`, not `error` (`Status.ErrorDetail`). The three conditions that must all hold, and the load-bearing doc comment (`// NOT rendered in stdout`) that stops a future maintainer from "fixing" the table asymmetry. Why a five-sentinel taxonomy was rejected: zero branching consumers.
- `cleanup-context-discipline.md` — orchestrator cleanup MUST run on a `context.Background()`-derived bounded context, never the caller's request ctx; otherwise SIGINT cancels the cleanup it triggered. Helper: `newCleanupContext()` in `internal/deploy/service.go`.
- `label-gated-orphan-recovery.md` — recover orphaned named artefacts on next run by gating on a creator-set label, not on the name alone; `decloud.service=<name>` plus the `Inspect → state+labels` JSON shape.
- `exit-code-sentinel-not-context-err.md` — CLI exit-code mapping matches the package sentinel (`deploy.ErrInterrupted`) only; bare `context.Canceled` / `context.DeadlineExceeded` route to `ExitInternal` and the negative test cases lock that contract.
- `gomock-fifo-matching.md` — `go.uber.org/mock` matches expectations FIFO, not LIFO; harness `AnyTimes()` defaults need an explicit opt-out option for tests that want a different response.
- `cancellation-symmetry-audit.md` — when fixing a `context.Canceled` mis-wrap at one site, audit every sibling forward-progress branch on the same request ctx; Linus's iter2 Issue 1 was the §3.4.5 sibling caught only on impl re-review, not in the v2 plan pass.
- `two-sentinels-for-two-failure-modes.md` — two semantically distinct rejection reasons get two distinct sentinels (not one umbrella); test pattern is `errors.Is`-positive AND `errors.Is`-negative-on-the-other, so a future "simplification" that folds them fails at PR time. Live: `ErrEmptyService` + `ErrInvalidService` in `internal/dockerdrv/driver.go`.
- `identity-as-field-not-derived.md` — flow identity (`Service`) as an explicit struct field; do NOT recover it via `strings.TrimPrefix(otherField, "prefix-")`. The TrimPrefix smell couples two fields by an invisible string-shape contract that breaks silently on future renames. Driver-layer guard catches zero-value accidents on new call sites.

## Implementation gotchas

- `envcap-portable-bash.md` — the macOS-bash-3.2-portable env.sh capture mechanism; why `compgen -e` + `${!name}` + `printf '\0'` and NOT GNU `env -0` (which silently no-ops on BSD env).
- `container-naming.md` — `decloud-<name>` in M1, `decloud-<name>-<deploy-id>` from M4; the rename is an explicit M4 deliverable, route all naming through one helper.
- **Docker network name single source of truth:** `caddy.NetworkName` (`internal/caddy/manager.go:20`, value `"decloud"`). Both `caddy` and `deploy` reference it; `deploy` already imports `caddy` and `caddy` does not import `deploy`, so the const lives in `caddy` cycle-free. Do NOT reintroduce a bare `"decloud"` literal — `deploy/service.go` was scrubbed of all five (the IPv6 task). The one place that still does NOT honor it semantically is the redeploy rollback path — see `m1x-backlog.md` item 13.
- `caddyfile-generator-facts.md` — what the generator emits and why each line is where it is: `protocols h1 h2` is an **allow-list** in the global options block (omitting `h3` is what disables HTTP/3); **`encode` is site-level-only — there is no global-options `encode`**, so "compression globally" means one line emitted per site block, per hostname (the mirror image of `protocols`; hold the pair in your head together); the global block MUST be first (load-bearing ordering, locked by test); and `match` cannot protect a streaming service — only omitting `encode` can.
- `docker-bridge-dns.md` — `decloud-<x>` short names only resolve from inside the `decloud` user-defined bridge; host processes fall through to host resolver and dial the host's own AAAA. Class-of-bug that shipped as M1.0 Caddy. Also: when a tech plan corrects an architectural assumption, promote it to `_ai/decisions/` — corrections buried in tech plans don't get audited against new code.

## Review discipline

- `apidocs.md` — doc-writing notes: `_docs/` is plain Markdown, no build step (NOT a Next.js app despite the filename); where operator-facing port/protocol facts live; **why lives in `_ai/decisions/`, never `_docs/`**; amend a disproven Decision with a dated subsection, never delete the reasoning; **`_tasks/` is immutable — plans are history, code is truth, the decision record outlives both**; the TOML top-level-key-above-the-first-`[table]` trap; "byte-asserted; pending operator `caddy validate`", never "validated".
- `readme-mid-build-honesty.md` — a mid-build project's README leads with a **dated, tagged Project Status before any install step** (`(SHIPPED)`/`(PLANNED)`, two states only, "As of <month year>" is load-bearing). Tone rules: no apology, no "still missing", no "should eventually". Don't write a design doc and call it a README — Architecture is ~5 lines; past 12 it's metastasizing. Explicit cut list for a one-maintainer pre-1.0 repo (badges, FAQ, CHANGELOG — `_tasks/` is the de-facto changelog).
- `review-bar-by-surface.md` — **the front-page bar is not the code-review bar.** Kevlin's "does it parse" and Linus's "are the load-bearing claims correct" are right for code; for README/LICENSE the bar is "would I be embarrassed if a peer saw this", and Don can upgrade both reviewers' "non-blocking" to blocking. Bounded by three conditions (reader-facing + genuinely cheap + non-fixing compounds); does NOT apply to wording the reviewers considered and defended. Single-pass and bounded is what separates it from bikeshedding.
- `doc-examples-verified-not-typed.md` — a fenced block claiming to be CLI stdout is a **byte-level contract**: generate it through the real code path and `diff` before commit, never hand-type it. Raymond hand-typed tabwriter padding (~22 chars vs the real ~13), flagged the risk himself, and drifted exactly as warned; Don promoted the "non-blocking nit" to blocker. "Roughly like" is not cover — it softens the contract for the author, not the copy-paster. The test layer cannot guard this (see `tabular-output-contract-tests.md`); review discipline is the only guard.
- `cross-ref-content-not-line-number.md` — cite **content, not `file.md:NNN`**, in any prose-side cross-reference. Line cites rot silently (a README rewrite 278→154 lines left `README.md:215` pointing past EOF; four files hit in one sweep). Tense-mark historical cites; forward-point when a contract moves. `_tasks/` is exempt — those cites were true when written.
- `tabular-output-contract-tests.md` — for `text/tabwriter` output, assert header fields present + rows present + row order, via `strings.Fields`; **never assert tabwriter's bytes** (column widths shift the day a longer fixture name lands) — that's the change-detector test CLAUDE.md bans. Helper shape lives in `internal/cli/lifecycle_commands_test.go`. Carve-out: single-row fixed-`Fprintf` paths, where full-line `assert.Equal` IS the contract.
- `absence-claims-need-a-search.md` — **the centerpiece.** "A presence claim is confirmed by an observation; an absence claim requires a search — over the space the claim quantifies, not the artifact in front of you." Four errors survived the compression task; all four absence-shaped, zero false positives. Recipes per claim shape ("only" → grep the call sites; "complete" → grep the request's nouns, look at the zeroes; "must not warn" → enumerate the property's states, not the code's branches). Joel: "a numbered list is where completeness goes to die." Praising a point in review is not requiring it in a spec. Rigor about what's present generates the *feeling* of verification, and the feeling is what stops the search.
- `false-greens.md` — three tools that report success while answering a different question: `gofmt -l` exits 0 whether or not it lists files (`&& echo clean` is a false green — test output emptiness); `go test` `ok (cached)` on mutated source is not evidence (`go clean -testcache` / `-count=1`); with parallel agents on one branch **staging is not a lock** — `git commit` takes the whole index, so commit with an explicit pathspec and verify with `git log -S`.
- `doc-grep-discipline.md` — when `_docs/*.md` shows a literal error string, `grep -F` it against the source. Two M1 doc-fab incidents (`install.md:173`, `:189`) both showed renderings that didn't match the wrap chain the code actually emitted. If the bytes are genuinely variable, frame them as variable — don't fabricate a clean example. Extension: applies to slog messages quoted in operator runbooks too (`usage.md:235`/`:237` drift across deploy-cleanup iter2). Two more halves: **label relayed claims as relayed, naming the relayer** (the only reason a wrong upstream claim didn't become permanent on the compression task), and **a doc writer's job is accuracy, not obedience** — Raymond overrode two seniors' instruction against the code and was right.
- `fix-now-while-fresh.md` — Don's repeated rule for in-task defects: fix in scope when mechanical + same-file + <5-minute floor + on-theme; defer when it requires new architecture or a different package's review surface. Captures the lockdown rationale across deploy-cleanup v2.1 and v2.2.
- `phantom-scope-kill.md` — inverse of fix-while-fresh: when handed-down prose names "X hardening" or "Y improvements" without a runtime/test referent, trace four ways before letting it expand scope; if all traces empty, kill the phrase explicitly. M2 killed "env-file hardening" as residue from the M3a-bundle resequence.
- `stderr-substring-canary.md` — branching on a third-party tool's stderr is fundamentally brittle; the mitigation is a canary test that fails loudly when the upstream wording shifts. Match canonical strings only, co-locate detection with its single caller (not the driver), lock with sub-tests-per-substring + a negative branch assertion. Live example: `isPortsBoundErr` in `internal/caddy/manager.go`.
- `guard-fires-before-exec.md` — rejection tests for guards-before-side-effects assert `assert.Empty(t, records)` on the recording fake-exec, not just `require.Error`. A future refactor that moves the guard AFTER `cmd.Run` still returns an error and silently leaks the side effect; the negative-record assertion is the lock. Pairs with the no-Docker-on-dev-box constraint that already forces argv-recording test shape.
- `scripted-exec-harness.md` — `internal/dockerdrv` has two fake `cmdFactory` flavours: `recordingFactory` (no-op + record argv) and `scriptedFactory` (record argv + run `/bin/sh -c <script>` so the fake's exit code/stdout is scriptable per call). Use scripted when a branch depends on a PRIOR docker call's result — e.g. `NetworkEnsure`'s inspect-fails-then-create path (`if [ "$2" = inspect ]; then exit 1; fi`). Assert create-path argv by index-reading the value after `--subnet`, not flat-slice equality. No daemon required.
- `sealed-at-create-lock-with-notcontains.md` — when external state is sealed at create-time (Docker's `HostConfig.LogConfig`), the lifecycle-path argv tests carry `assert.NotContains` rows for every create-time flag. Positive `Contains` on the create path + negative `NotContains` on every start/restart path. Locks both directions of the invariant. Live: `TestCLIDriver_StartArgs` rejects `--log-driver` and `--log-opt`.
- `compile-clean-not-run-clean.md` — two paired rules: (1) opt-in tests that need real external services need an actual PASS run-log, not a `go build -tags integration` log; (2) opt-in tests do NOT gate squash-merge when the user-visible surface is independently unit-tested. M2 v1 alpine-no-Cmd bug + closeout run-log-gate reversal.

## Cross-references for shapes worth borrowing

- **`PortMap.HostBind` as a first-class field, not a string-formatting trick.** Dual-stack publishing (`0.0.0.0` + `[::]`) is six PortMap entries with explicit host-bind, NOT a `formatPortMap` that conditionally brackets IPv6. The formatter splices verbatim and the doc-comment forbids auto-bracketing. See `internal/dockerdrv/driver.go::PortMap` and `cli_driver.go::formatPortMap`, locked by `TestFormatPortMap_DoesNotAutoBracketIPv6`. Rationale lives in `decisions/caddy-runs-in-container.md`.
