# Monospaced example blocks in `_docs/` must be generated, not hand-typed

When a Markdown doc shows a fenced example block that purports to be literal stdout from a CLI command, the bytes inside the block ARE a contract surface — the implicit promise is "this is what you will see." Hand-typing the example to "approximate" what the command produces is exactly the drift class that publishes docs lying about the binary's behaviour. Generate the example from the same code path the CLI uses, then paste.

## The failure mode

`_tasks/2026-05-13-status-list-all-services/` — Raymond hand-typed two example blocks in `_docs/usage.md` §4.1 and §5 to approximate `tabwriter.NewWriter(out, 0, 0, 2, ' ', 0)` output. Kevlin's review caught the drift byte-for-byte: the CONTAINER column was padded to ~22 chars in the docs, ~13 chars in reality (`padding=2` means exactly two spaces after the widest cell). Raymond himself had flagged the risk in his report ("the spacing in the example is hand-typed to approximate tabwriter's two-space padding"). The drift happened exactly the way he warned it might.

Don's round-2 verdict: docs that lie about literal stdout are user-facing wrongness, even when classified by the reviewer as a "non-blocking nit." Embarrassment-driven-development bar applies. Five-minute fix; do it before squash-merge.

## The discipline

When a doc shows a fenced block claiming to be stdout from `<command>`:

1. **Generate the bytes.** Either pipe a real fixture through the actual code path, or write a one-off `_test.go` / `main.go` that runs the same writer/format with the same config the CLI uses. For tabwriter, that's `tabwriter.NewWriter(out, <args matching the CLI>)`. For `text/template`, instantiate the template. For `json.MarshalIndent`, call it.
2. **Diff before commit.** `diff -u <generated> <existing-doc-block>` should be empty.
3. **If the generator is non-trivial**, leave a comment in the doc near the block: `<!-- generated by go run ./internal/scripts/render_status_examples.go -->`. Future maintainers know not to hand-edit.

## When this applies

- Any fenced block in `_docs/` or `README.md` purporting to be CLI stdout/stderr.
- Any fenced block showing a config-file rendering generated by the binary.
- Any fenced block claiming to show a `cat <log-file>` excerpt of binary-generated logs.

When this does NOT apply: prose snippets describing what a command does ("the binary prints a header line, then one row per service"), generic example invocations (`$ decloud status`), and shell command-line fragments that don't claim to be output bytes.

## Anti-pattern in practice

```markdown
The output looks roughly like:

    NAME        STATE    CONTAINER             DEPLOY                  DEPLOYED_AT
    bar         stopped  decloud-bar           20260426-102001-aa11bb  2026-04-26T10:20:01Z
```

Two failures:

1. "Roughly like" gives the author cover to hand-type. They will. The `roughly` softens the implicit contract, but a copy-paster reading the docs will not notice the softener and will report the discrepancy as a bug.
2. Padding is wrong (`CONTAINER` column padded to widest-cell + arbitrary spaces, not + the configured 2 spaces). The next maintainer who runs `decloud status` and diffs against the doc files a bug. The cost of the fix is two paste operations; the cost of leaving it is operator trust erosion.

## Why the test suite doesn't catch this

`_ai/tabular-output-contract-tests.md` carves tabwriter byte output OUT of the test contract — the test layer asserts on header presence and row identity, not on column widths. That carve-out is correct (column widths are not the operator contract; they shift with the widest cell). But it means the test suite cannot guard the doc example blocks. The guard is review discipline and the "generate, don't type" rule.
